# Launch gates and conditional roadmap

**Status:** PROPOSED, research only. Nothing here authorizes implementation, outreach, spending, installation or publication. **Current decision:** NARROW. No customer value, retailer grant, tested build, approved affiliate income or public release has been demonstrated.

Day 1 starts separately authorized work. Windows and effort are planning assumptions for one developer, excluding recruitment/negotiation delays and specialist review. See [validation](09-validation-and-growth.md), [backlog](13-build-backlog.md) and [costs](10-business-and-costs.md).

## 1. Three distinct product stages

| Stage | Deliverable and permitted promise | Entry and exit conditions |
|---|---|---|
| **P0 — private founder prototype** | Native MV3/TypeScript; one semantic HTML/CSS popup; structured manual facts and labeled synthetic fixtures; local saved offers, provisional comparisons and the user's own observations. `storage` only. | Starts only after a new implementation instruction. Exit requires verified local behavior and observed task value. No retailer reader, accounts, telemetry, backend, watches, alarms, notifications or affiliates. |
| **P1 — permission-backed private pilot** | An eligible bundled local reader, or a permitted merchant file reviewed by the founder for research/manual entry. No customer file import or hosted ingestion. | Signed scope, usable sample, privacy/security review, approved cohort and working correction/disable process. |
| **P2 — public MVP** | Bounded capabilities that passed P1; a single-merchant explainer is possible if its own value gates pass. Hosted canonical-ID catalog/API is conditional on licensing and demonstrated necessity; identity and saved offers remain local. | All public-release gates below pass. Cross-store comparison additionally requires two independently eligible merchant/source integrations with exact overlapping offers. Public release is optional. |

Two sellers on one marketplace do not by themselves establish two eligible cross-store integrations. Each intended collection and display method needs its own authorization.

The [contracts](06-data-and-api-contracts.md) govern P0 limits, retention and save behavior. Never silently evict records or label an incomplete write saved; explain profile-loss and export limitations.

## 2. First 30 days: learn before expanding

| Window | Work and evidence produced | Founder effort assumption | Cut line |
|---|---|---:|---|
| Days 1–3 | Confirm the mouse segment and notebook hypothesis; prepare two labeled synthetic task sets, answer keys, consent process and one permitted recruitment channel | 4–6 h | No real retailer adapter or public distribution |
| Days 4–7 | Start non-leading interviews and baseline tasks; record actual device, current shopping occasion, existing method and recruitment denominator | 5–8 h | If too few eligible shoppers, investigate targeting; do not broaden categories automatically |
| Days 8–14 | Finish 10–12 sessions where possible; test the proposed card; make one focused revision; send separately authorized, scope-specific merchant inquiries | 7–11 h | If manual entry adds work without improving decisions, reconsider the notebook before coding further |
| Days 15–21 | If justified and authorized, run the smallest P0 slice; verify save/reopen/export/delete, no network/site access and error states; inspect a merchant sample only if granted | 8–13 h | No grant means no real reader or scheduled collection; retain manual/synthetic scope |
| Days 22–30 | Follow up on actual shopping occasions, score outcomes, compare support effort and review source access/cost gates; write go/narrow/pause decision | 4–6 h | Do not call researcher-prompted activity retention or partial samples validated demand |

Total: **28–44 founder hours**. If P0 exceeds this allowance, retain the observed mockup task and defer implementation. No public launch is required.

At day 30, document continue/narrow/pivot/pause/stop, including failed tasks, missing evidence and what would reverse the decision. A surface pivot needs fresh evidence.

## 3. Conditional days 31–90

| Window | Milestone if prerequisites pass | Effort assumption | Dependency and scope reduction |
|---|---|---:|---|
| Days 31–45 | Secure one valid method/field grant; review a permitted merchant file for research/manual entry; map variants and permissions; validate corrections and termination behavior | 10–18 h | No customer import or hosted ingestion. No agreement: pause P1. A seller API or affiliate link is not a substitute. [D01–D03](research/sources.md) |
| Days 46–60 | Run a small consented private pilot; measure accurate value, coverage, fresh observations and support burden; implement at most one eligible local reader | 15–27 h | If one merchant only, explain its offers; omit cross-store ranking. No usable overlap: omit comparison claims. |
| Days 61–75 | Harden the successful slice; label a matching benchmark; resolve at-rest protection, pre-install disclosures, accessibility, release identity and support | 15–25 h | Any unresolved critical correctness/privacy issue blocks public distribution. |
| Days 76–90 | If every gate passes, prepare a reviewable store package and budget; obtain final founder authorization; publish only after review and approval | 15–30 h | Fee unavailable, review delayed or licence incomplete: remain private. No launch deadline overrides a gate. |

Total 90-day assumption: **83–144 founder hours**. Include backend work only in conditional P2, if necessary and feasible within that allowance. Defer general AI, coupons/cashback, accounts, a mobile app, browser-closed notifications and extra categories.

## 4. Public-release evidence checklist

This is a stop/go record, not a claim that any control currently works.

| Gate | Required reviewable evidence | Current state |
|---|---|---|
| Actual user value | Task outcomes with denominators, critical-error review, repeat occasions and founder support effort | **OPEN** |
| Retailer/source rights | Signed method/field/cadence/retention/display grants; expiry/deletion rules; two independently eligible merchant/source integrations with exact overlap if cross-store comparison is promised | **BLOCKED**; no eligible source |
| Honest price behavior | Exact identity, eligible costs, stock, gaps, provenance and the labeled benchmark passing the [testing](11-testing-and-operations.md) gate | **OPEN** |
| At-rest protection | Evidenced storage/key-management design or authoritative interpretation for the exact local data; no unsupported encryption claim | **BLOCKED** [T10, T36](research/sources.md) |
| Disclosure and consent | Consistent listing, pre-install notice, store dashboard answers, onboarding and measured data flows | **BLOCKED** [T37](research/sources.md) |
| Security and reproducibility | Reviewed manifest/bundle, no secrets/remote code, dependency/license audit, reproducible build and actual browser tests | **OPEN** [T09, T12](research/sources.md) |
| Accessibility and UX | Keyboard/screen-reader checks, readable status/error states, WCAG 2.2 AA target assessed on the built popup | **OPEN** [T32](research/sources.md) |
| Operating readiness | Support/corrections, tested export readability/completeness, internal interrupted-write/migration recovery, rollback and source-disable plan; backend restore only if a P2 service exists | **OPEN** |
| Cash and publication | Founder publisher account, ability to pay the verified **USD5** registration fee plus any transaction costs, final approval and store review | **BLOCKED** under literal zero extra cash [T14–T15](research/sources.md) |
| Ongoing cost | Measured workloads fit approved budget; quota degradation works; no production AI subscription assumption | **OPEN** |

Before final publication approval, prepare the artifact/version/checksum, real screenshots, feature/permission list, support/privacy/terms URLs, test results, limitations, rights record and cost cap. Clear the proposed branding. Store acceptance does not establish retailer permission or legal clearance.

## 5. Release, rollback and maintenance

Explain pilot limitations and obtain consent before any separately authorized installation. Keep distribution to the reviewed cohort.

Keep a last-known-good artifact and documented migrations; verify export readability and internal recovery before rollback. User backup import remains deferred; an export file is not a demonstrated restore feature. If a grant ends or an adapter fails, disable the source and mark affected facts unavailable. Packaged parser changes use the release process; bounded remote flags can disable reviewed behavior, never supply executable rules. [T12](research/sources.md)

A missing feed creates no observation; preserve gaps and stale labels. P0 has no alerts. Later browser checks require the browser running; closed-browser email/push needs new architecture, cost and consent decisions. [T01, T06–T07](research/sources.md)

Review corrections, source health and maintenance minutes weekly. Stop invitations and reduce supported offers when support exceeds founder capacity.

## 6. International expansion gate

Consider one further country/category only after repeatable value, licensed access, reliable matching, sustainable margin and manageable support. Recheck contracts, shipping/taxes, currency, product region, warranty, payment eligibility, privacy/consumer obligations and distribution rules.

A benchmark's merchant/reward network does not automatically transfer across countries. [M03–M08](research/sources.md) Translation and currency formatting cannot replace source and jurisdiction evidence.
